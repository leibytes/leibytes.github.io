# Linux磁盘挂载实操指南（CentOS7）

> 适用场景：云服务器新增数据盘，磁盘识别、格式化、挂载、永久挂载；重点区分挂载至空目录和挂载至非空目录的差异与风险，为运维踩坑总结。
> 
> 

## 前言

很多云服务器用户会遇到一个经典误区：云控制台已经把磁盘挂载到服务器实例上，但是 `df -h` 看不到这块磁盘空间。

原因：**云平台只是把硬件磁盘交付给服务器，操作系统层面还没有做文件系统、mount 挂载**。

三个基础概念回顾：

- 磁盘：块设备，如 `/dev/sdb`，只是一块裸硬件，本身不能直接存文件

- 文件系统：ext4/xfs，给磁盘打上文件系统标记，让系统可以读写文件

- 挂载点：Linux 目录（`/home`、`/data`），把磁盘关联到目录入口，访问目录就是访问这块磁盘

> 重要：Linux 一切皆文件，磁盘必须挂载到目录才能使用。
> 
> 

## 一、查看服务器识别到的磁盘与分区

### 1\. 首选命令 lsblk（推荐）

```bash
lsblk
```

输出示例：

```
NAME   MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
sda      8:0    0   40G  0 disk
└─sda1   8:1    0   40G  0 part /
sdb      8:16   0  300G  0 disk
sr0     11:0    1  506K  0 rom
```

解读：

- `sda`：系统盘，sda1 分区已经挂载到根 `/`

- `sdb`：新增 300G 数据盘，**没有分区、没有挂载点**，就是我们要操作的盘

- `MOUNTPOINT` 为空 = 未挂载

只看磁盘，不展示分区树：

```bash
lsblk -d
```

### 2\. 其他辅助查看命令

```bash
# 查看磁盘分区详细信息（root）
fdisk -l
# 查看磁盘、分区UUID、文件系统类型（写fstab用）
blkid
# 查看已经挂载的分区（看不到未挂载磁盘！）
df -h
# 查看内核识别的块设备
cat /proc/partitions
```

> 踩坑提醒：不要只用 `df -h` 判断磁盘，df 只能看到已经 mount 成功的分区，裸盘、未挂载盘不会输出。
> 
> 

## 二、磁盘格式化（准备文件系统）

> 前提：确认磁盘设备名，示例为 `/dev/sdb`，**一定要核对设备名，不要误格式化系统盘 sda！**
> 
> 

示例使用 ext4 文件系统：

```bash
mkfs.ext4 /dev/sdb
```

格式化完成后，用 blkid 校验：

```bash
blkid /dev/sdb
```

输出示例：

```
/dev/sdb: UUID="c3b6d83c-4695-4f37-bcd8-91040e923b53" TYPE="ext4"
```

拿到 UUID，后续用于永久挂载。

> 格式化会清空磁盘上所有数据！已有数据的磁盘严禁执行 mkfs。
> 
> 

## 三、磁盘挂载：两种场景（重点）

### 核心原理

当把磁盘 `mount` 到某个目录时：**该目录原有内容不会被删除，只是被临时"遮挡"，umount 卸载磁盘之后，原来的内容会重新显示出来。** 这是绝大多数运维踩坑的根源。

### 场景 A：挂载到【空目录】（推荐，风险最低）

适用：新建目录作为数据目录，或者原有目录本身为空（例如 `/home` 为空）。

示例：把 `/dev/sdb` 挂载到 `/home`，`/home` 当前无任何文件。

1. 确认目录为空

```bash
ll /home
```

输出总用量 0，无文件，满足条件。

1. 临时挂载（重启失效）

```bash
mount /dev/sdb /home
```

1. 验证挂载

```bash
df -h
```

此时可以看到 `/home` 已经占用 sdb 的 300G 空间。

1. 配置永久挂载（重启自动挂载）

编辑 `/etc/fstab`：

```bash
vi /etc/fstab
```

添加一行（使用 UUID，比设备名稳定，云服务器设备名偶尔会漂移）：

```
UUID=c3b6d83c-4695-4f37-bcd8-91040e923b53 /home ext4 defaults 0 0
```

校验 fstab 配置是否写错（非常重要，写错服务器开机失败！）：

```bash
mount -a
```

没有报错代表配置正常。

优点：目录为空，不存在数据遮挡问题，直接挂载即用，不需要迁移数据。

### 场景 B：挂载到【非空目录】（高风险，必须先备份迁移）

适用：目录里面已经有业务数据，希望把后续数据存到新磁盘，原有数据迁移到新盘。

> 禁止直接 mount！直接挂载后，进入目录只能看到新磁盘内容，原有数据被遮挡，容易误以为数据丢失。
> 
> 

完整步骤：

1. 先备份目录内原有数据（迁移）

```bash
# 创建临时中转目录
mkdir -p /mnt/tmpdata
# 把/home下所有数据复制到临时目录
cp -r /home/* /mnt/tmpdata
```

1. 挂载磁盘到 `/home`

```bash
mount /dev/sdb /home
```

1. 把备份的数据还原回挂载后的 `/home`（此时 /home 已经是新磁盘）

```bash
cp -r /mnt/tmpdata/* /home/
```

1. 确认数据正常后，清理临时备份

```bash
rm -rf /mnt/tmpdata
```

1. 同样配置 `/etc/fstab` 永久挂载，`mount -a` 校验。

> 一句话总结：非空目录挂载，流程是【备份 → 挂载磁盘 → 恢复数据到新盘】。
> 
> 

## 四、卸载磁盘命令

```bash
umount /home
# 或者写设备名
umount /dev/sdb
```

> 卸载时如果提示 target is busy：代表有进程正在访问这个目录，退出目录、停止业务进程再卸载。
> 
> 

## 五、重要注意事项与避坑清单

1. **区分删除目录和挂载遮挡**：挂载遮挡不等于删除文件。只要不格式化，umount 之后原有文件还在；但如果挂载之后，在新磁盘里写入同名文件，覆盖是另外一回事。

2. **fstab 配置校验是生命线**：写完 fstab 一定要执行 `mount -a`，没有报错再退出。如果 fstab 写错，服务器重启会进入 emergency 紧急模式，无法正常启动。优先使用 UUID，不推荐直接写 `/dev/sdb`。

3. **分清系统盘和数据盘**：操作前反复 lsblk 确认设备，严禁 mkfs、mount 操作到 sda 系统盘，会直接系统崩溃、数据丢失。

4. **df 和 lsblk 的区别**：lsblk 查看所有识别到的磁盘，包含未挂载裸盘；df \-h 只查看已经挂载成功的分区，排查新盘不要只用 df。

5. **业务目录建议规划**：业务数据尽量单独规划挂载目录，例如 `/data`，不要直接覆盖系统目录；如果是 /home 用户目录扩容，优先按上面迁移流程操作。

6. **云服务器额外提醒**：云控制台的磁盘挂载，只是硬件层面的关联，操作系统内仍然需要格式化 \+ mount，这是新手最高发疑问。

7. **权限问题**：挂载完成后，如果业务用户无法读写目录，检查目录属主、权限（chown、chmod）。

## 六、快速复盘命令清单

```bash
# 查看磁盘
lsblk
# 格式化
mkfs.ext4 /dev/sdb
# 临时挂载
mount /dev/sdb /home
# 验证挂载
df -h
# 获取UUID
blkid /dev/sdb
# 校验fstab
mount -a
# 卸载
umount /home
```
